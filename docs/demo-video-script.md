# Demo video script

Generated by `scripts/make_demo_video.py` from the same scene definitions that drive the recording, so the on-screen script and this file cannot drift apart. Planned length: 110 s (limit: 120 s).

**Microphone.** Microphone: a recorded question played through Chrome's fake microphone. The page runs its real getUserMedia → AudioWorklet → WebSocket path; models and server are the real ones. To use your own voice, record the questions and pass them with `--mic scene=file.wav`.

## What the brief asks the video to show, and where

| Brief item | Scene · step |
|---|---|
| User speaks into a microphone | English · step 1 |
| ASR transcribes in real time (partial text) | English · step 2, Mandarin · step 2 |
| RAG retrieves context | English · step 3 |
| Streaming LLM generates the response | English · step 4 |
| TTS synthesizes and plays the audio | English · step 5 |
| Latency highlighted ("Response time") | English · step 6 (blue box on the Latency panel), Mandarin · step 6, the latency card |
| Streaming extras: barge-in, refusal, Mandarin | Scenes 2–4 |
| Streaming vs batch baseline | latency card |

## Timeline

1. **Title card** (7 s): what the system is and what the video checks.
2. **English question** (up to 14 s)

   1. User speaks into the microphone: 16 kHz mono PCM, 100 ms frames, one WebSocket.
   2. Streaming ASR: the partial transcript updates while the user is still speaking.
   3. End of speech: retrieval (FAISS + BM25) finds the knowledge-base context {ids}.
   4. Streaming LLM (Qwen2.5-0.5B, CPU only): tokens appear as they are generated.
   5. Streaming TTS synthesizes the answer in small chunks and plays it as soon as the first chunk is ready.
   6. Response time: {latency}, from the end of the user's speech to the first audio (target < 1.5 s).

3. **Mandarin question** (up to 13 s)

   1. Mandarin: its own streaming ASR model and Chinese voice, the same pipeline.
   2. The partial transcript (Simplified Chinese) streams in while the user speaks.
   3. Retrieval over the Chinese knowledge base finds {ids}.
   4. The answer streams token by token.
   5. The Chinese voice synthesizes and plays the reply.
   6. Response time: {latency}.

4. **Barge-in: interrupting the answer** (up to 22 s)

   1. The user asks a question…
   2. …and VORA starts speaking the answer.
   3. Barge-in: the user talks over the answer. Playback stops at once, and the LLM and TTS are cancelled if they are still running.
   4. The new question is answered. Response time for the new question: {latency}.

5. **Off-topic question** (up to 11 s)

   1. An off-topic question: nothing about it is in the knowledge base.
   2. The transcript still streams in.
   3. No relevant context, so VORA says it is not sure instead of making something up.
   4. Spoken refusal. Response time: {latency}.

6. **Real human voice (phone quality)** (up to 14 s)

   1. Real human speech: a phone recording from the public MInDS-14 dataset (CC-BY-4.0), 8 kHz.
   2. Phone-quality speech is hard: the transcript is rough (WER 42–49% on this set).
   3. A banking question is outside the VORA Box knowledge base: VORA {outcome}.
   4. Spoken reply. Response time: {latency}.

7. **Latency card** (9 s): the takes in this video, the benchmark on real recordings, streaming vs batch.
8. **Gates card** (11 s): every brief target with its real PASS / FAIL / UNVERIFIED.
9. **Limits card** (9 s): what is not met or not measured.
